# 真店验收清单（W5）

> 每一次插件版本发布前的最后一道门。在 awwwstore.com（dogfood 店）上跑。
> 原则与门户仓一致：**「看到了才算数，跑过了不算数」**——每步都要有眼睛看到的结果。

## 前置事实（2026-09-19 核实）

- awwwstore 的 **HPOS 是开的**（WooCommerce → 设置 → 高级 → 功能 → 订单数据存储 = 高性能订单存储，兼容模式关）。
- 切经典存储**当下切不了**（「目前有订单尚未同步」，需先同步订单）。
- 所以本轮验收覆盖 **HPOS 路径**（meta box 回调收到 `WC_Order`）。经典路径（`WP_Post` → `wc_get_order`）是同一个函数里的分支，Woo 7.1+ 默认 HPOS，多数真实商户都在 HPOS —— 经典路径在能切的店上补验即可，不作为发布阻塞。

## 步骤

### ① 安装与骨架

1. 上传 zip → 启用 → 插件列表里出现 **365nails Sync**，版本号与 tag 一致。
2. **禁用 WooCommerce** → 应看到错误提示「365nails Sync requires WooCommerce…」且插件被自动停用（或 admin notice）。重新启用 Woo + 插件。

### ② HPOS 下的面板（核心）

1. 打开任一订单（如 #3156）→ 右侧应有 **「365nails Dropshipping」** 面板。
2. 无运单 meta 时：一句平静空态（"No 365nails tracking on this order yet…"），**不报错、不出 PHP 警告**。
3. 在「自定义字段」里加三条：`_365_tracking_number` = `TEST-365-001`、`_365_carrier` = `Test Carrier`、`_365_tracking_url` = `https://example.com/track/TEST-365-001` → 更新。
4. 面板应显示 **Carrier: Test Carrier** 和可点的 **TEST-365-001**（链接到新标签页）。

### ③ 客户邮件

1. 给该订单填一个能收信的账单邮箱（验收用测试邮箱），订单操作 → 重新发送「订单详情」给客户。
2. 收件箱里应看到 **Tracking** 块（承运商 + 可点运单号），样式与 Woo 邮件其它块协调（边线节奏一致）。
3. 用纯文本邮件再发一次（若有该开关），应是纯文本行而非 HTML 残留。

### ④ 新版提示（v0.2.1+）

1. 把一个旧版（如 0.2.0）装上 → `plugins.php` 应出现「A newer 365nails Sync is available: 0.2.1」提示。
2. 断网（或拦 GitHub API）刷新页面 → **不出错**（抓取失败静默）。

### ⑤ 断网演练

1. 把 webhook 投递地址改成会失败的 URL（或让门户端点 5xx）→ 店里下一单 → **webhook 失败不影响插件**（面板照常渲染既有 meta；对账 cron 在门户侧捞单，与插件无关）。

### ⑥ 卸载安全

1. 停用 + 删除插件 → 订单上的 `_365_tracking_*` meta **仍在**（卸载不删商户数据）。
2. `nai365_sync_version` option 残留可接受（不重装不影响）。
